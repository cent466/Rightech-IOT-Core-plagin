# Готовые файлы вместо API

Плагин не подключается к Rightech. Результат работы — файлы, которые пользователь сам загружает в интерфейсе.

## Что отдавать по типам

| Тип | Файл | Как попадает в Rightech |
|---|---|---|
| Модель | `<дата>_Модель_<имя>.json` | Создание модели → импорт из файла (документировано) |
| Сценарий | `<дата>_Сценарий_<имя>.json` | Создание сценария → импорт из файла (документировано) |
| Обработчик | `<имя>.json` + `<имя>.js`/`.ts` | Импорта нет: создать обработчик, вставить код, сохранить |
| Геозона | `<дата>_Геозона_<имя>.json` | Импорт не документирован: создать на карте, JSON — эталон геометрии |

## Сборка файла

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/make_import_file.py" entity.json --store models
```

В Codex путь к плагину — `${PLUGIN_ROOT}`. Скрипт валидирует сущность, убирает служебные поля (`_id`, `owner`, `group`, `time`, `_at`, а в дереве модели — `_parentId`, `_inactive`, `copy`, `_isRoot`, `_levels`, `_dataPath`), заворачивает результат в оболочку экспорта и сохраняет в `rightech-output/`.

Оболочка повторяет формат платформенного экспорта и официальных примеров импорта:

```json
{"version": 1, "origin": "dev.rightech.io", "time": "2026-11-14T12:00:00.000Z", "store": "models", "data": { ... }}
```

`origin` меняется флагом `--origin`, если у пользователя другой сервер.

## Инструкция пользователю

Всегда заканчивай короткой инструкцией под тип:

- **Модель:** «Модели → плюс → Создать → Импорт → выбрать файл → Создать. После импорта проверьте число параметров».
- **Сценарий:** «Сценарии → плюс → Создать → Импорт → файл. После импорта назначьте модель объектам и сопоставьте кросс-элементы, как требует платформа». Идентификатор модели в файле должен соответствовать уже созданной модели.
- **Обработчик:** «Обработчики → плюс → имя и язык → вставить код из `.js`/`.ts` → Сохранить. Связи `parameters`/`crossMappings` задайте в интерфейсе: они ссылаются на уже существующие сущности».
- **Геозона:** «Геозоны → плюс → тип «полигон» → нарисовать по координатам из файла; готового импорта для геозон в документации нет». Предложи также отдать список координат текстом.

## Что показать в ответе

Небольшой JSON (до ~200 строк) приведи целиком в ответе вместе с путём к файлу. Большой (модель на сотни узлов, полигон на тысячи точек) — не вставляй полностью: дай путь, размер, сводку и первые элементы.

## Документация перед выдачей

До генерации используй `rightech-research` для самостоятельного поиска неизвестной структуры или деталей устройства. В результирующем ответе коротко перечисли найденные источники; если поиск не нашёл подтверждения, укажи это и запроси недостающий материал. Не подменяй исследование просьбой «загрузите документацию».

## Проверка перед выдачей

1. Валидатор: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/validate.py" entity.json --store models --mode new` — без ошибок.
2. Покажи, что вошло в файл: имя, тип, число узлов/состояний/точек, отличия от ближайшего образца.
3. Предупреди, что файл не отправлялся в аккаунт и что импорт выполняет пользователь.

## Запрещено

- Обещать, что импорт сработает для геозон и обработчиков: для них его нет в документации.
- Оставлять в файле служебные поля и идентификаторы чужого аккаунта.
- Класть в файлы токены, пароли, ключи.
