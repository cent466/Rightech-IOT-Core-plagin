# Геозоны

## Перед генерацией

Сначала `rightech-research`: проверь официальную справку Rightech о типах геозон и точном JSON-формате нужной фигуры. Затем `rightech-questions` — спроси о том, чего нет в найденной документации и правилах. Готовых экспортов-геозон в плагине нет: если нужен эталон формы, попроси у пользователя экспорт своей геозоны.

## Формат (подтверждено двумя образцами)

```
{
  "name": "...",
  "color": "#2986FF",
  "style": {"fillOpacity": 0.2, "opacity": 0.75, "weight": 2},
  "shape": {"type": "polygon", "points": [[широта, долгота], ...], "cutouts": [{"type": "polygon", "points": [...]}]},
  "floors": [],
  "props": {}
}
```

- Порядок координат во **внутреннем** формате: **[широта, долгота]**. Подтверждено диапазонами: Владимирская область 55–56 / 38–43, Ленинградская 59.6 / 30.06. Перепутанный порядок перевернёт зону.
- Контур в рабочих образцах **не замкнут** (первая точка не равна последней). Не замыкай его и не требуй замыкания.
- `cutouts` — вырезы внутри полигона, каждый тоже `polygon`.
- `color` — `#RRGGBB`; `style` — прозрачность и толщина.

## Вкладка «Код»: принимается и GeoJSON

Проверено пользователем в аккаунте (2026-11-14): во вкладку **Код** геозоны-полигона вставляется GeoJSON `Feature` с `geometry.type: "Polygon"` и замкнутым `coordinates`; пары — **[долгота, широта]**. Не переписывай GeoJSON в `shape` и никогда не меняй порядок координат.

## Обработка входного GeoJSON

Перед подготовкой файла сначала разбери и проверь его, затем выбери один из случаев:

1. **`Feature` с `Polygon`:** это уже формат для вкладки «Код». Проверь JSON, координаты и замкнутость каждого кольца; сохрани geometry и все кольца без изменения порядка/значений (кроме отдельно согласованного упрощения). Игнорируй только свойства `properties`, если нужно; покажи число вершин и географические границы.
2. **`FeatureCollection`:** сначала найди целевой объект по `id`, `properties.name`, `name:ru`, `short_name`, `loc_ref` или `@id`. Не объединяй features автоматически; точки/остановки и нецелевые объекты не включай. Если подходящих полигонов несколько, спроси пользователя, какой выбрать.
3. **`MultiPolygon`:** это несколько самостоятельных полигонов, не одна линия. Уточни, нужен ли один компонент или все; если Rightech-код требует один Polygon, выбери компонент только по явному ответу или однозначному целевому feature. Не выбирай автоматически «самый большой».
4. **`LineString` / `MultiLineString`:** это линии, не полигон. Не замыкай дорогу в кольцо автоматически: у МКАД это может создать огромную зону внутри кольца вместо полосы дорожного полотна. Спроси, нужна ли область внутри кольца или полоса/коридор вдоль дороги. Для полосы обязательно запроси ширину буфера и подходящий способ построения polygon; не выдумывай её.
5. **`Point`, `MultiPoint`, отсутствующая/неизвестная геометрия:** это не полигональная геозона; объясни несовпадение типа и попроси правильную геометрию/уточнение.

`python scripts/geojson_zone.py input.geojson -o zone.geojson` подготавливает один однозначный Polygon и сохраняет исходные координаты/кольца. Для выбора в FeatureCollection: `--feature "МКАД"`; для части MultiPolygon: дополнительно `--polygon-index 0`. Скрипт отказывается конвертировать line-only данные или неоднозначные полигоны, не замыкает и не переворачивает кольца молча. `--simplify` используй только после явного согласования упрощения; сообщи допуск, число точек до/после и границы.

Перед выдачей пользователю проверь, что выход — валидный `Feature`/`Polygon`, координаты остались в GeoJSON-порядке `[долгота, широта]`, кольца замкнуты и совпадают с выбранной геометрией, и сообщи, что было исключено/упрощено. При ошибке `Invalid GeoJSON object` проверь точный текст редактора на обрезку, лишние JSON-объекты/символы и неверный тип геометрии.

Для внутреннего формата экспорта (`shape`) действуют отдельные правила ниже; GeoJSON во вкладке «Код» остаётся с парами `[долгота, широта]`.

## Ограничения

- Круг: в локальных образцах его нет. Сначала найди точный формат в официальной документации Rightech. Если официальная документация не описывает JSON-структуру круга, попроси пользователя загрузить экспорт круглой геозоны из своего аккаунта; до получения эталона круг не генерировать.
- Большие полигоны: образец Владимирской области — 8 636 точек и 551 КБ. Предупреди о размере и уточни, можно ли упростить контур.
- Привязка к объектам и события входа/выхода образцами не покрыты: найди официальный способ в справке Rightech, а если JSON-форма настройки не документирована — попроси экспорт/пример из аккаунта.

## Точные контуры: Overpass

Координаты реальных объектов (МКАД, район, озеро, промзона, граница региона) **не придумывай**. Точный контур берётся из OpenStreetMap через Overpass Turbo: отправь пользователю инструкцию целиком, не заменяя её пересказом.

1. Открой `https://overpass-turbo.eu` — регистрация не нужна.
2. Вставь запрос в левое окно. По relation из OSM: `[out:json][timeout:60];rel(2094222);out geom;` По названию: `[out:json][timeout:60];nwr["name"="МКАД"](55.4,37.2,56.0,38.0);out geom;` Граница региона: `[out:json][timeout:60];rel["name"="Московская область"]["admin_level"="4"];out geom;` Подставь имя объекта и примерный охват (юг,запад,север,восток) вокруг него, чтобы запрос не ушёл по всей стране.
3. Нажми «Выполнить» и убедись, что на карте подсветился нужный объект.
4. «Экспорт» → «Данные» → GeoJSON.
5. Пришли получившийся файл (или его содержимое).

Что приходит и что с этим делать:

- Выгрузка обычно `FeatureCollection`: дорога может быть `MultiLineString`, граница — `Polygon`/`MultiPolygon`, рядом могут быть несвязанные `Point` (остановки). Во вкладку «Код» передаётся один `Feature` с `Polygon`, поэтому коллекцию нужно сначала разобрать по целевому feature и геометрии.
- Если в целевом feature уже `Polygon`, подготовь его скриптом `python scripts/geojson_zone.py overpass.json --feature "имя или id" -o zone.geojson`. Для единственной однозначной полигональной геометрии `--feature` не нужен. Для `MultiPolygon` укажи `--polygon-index N` только после выбора требуемой части пользователем.
- Скрипт сохраняет пары `[долгота, широта]`, все кольца выбранного Polygon и исходную геометрию, не объединяет объекты. При смешанной FeatureCollection выбери feature через `--feature`; точки не подходят для геозоны. Скрипт завершится с объяснением при line-only данных, незамкнутом кольце или неоднозначном выборе. Он не строит polygon из дорожной линии.
- Для `MultiLineString` остановись и выясни, нужна ли зона внутри замкнутого кольца или полоса дороги; для полосы спроси ширину буфера. Не выдавай автоматически замкнутую дорожную линию за полигон.
- Результат — обычный `Feature` с `Polygon`: вставь его во вкладку «Код» геозоны типа «Полигон» и сохрани. `--simplify` используй только с явного разрешения, затем сообщи число точек и границы до/после.
- Если Overpass недоступен, объект не находится или пользователь не может выгрузить — попроси файл выгрузки либо нарисуй зону по подтверждённым вершинам. Не подставляй координаты «по памяти».

## Проверка

Проверку запускай bundled-валидатором `scripts/validate.py` навыка `rightech-output`; если кодовый инструмент не видит ресурс другого навыка, сообщи об этом и не утверждай, что скрипт запускался.

Валидатор проверяет пары чисел, диапазоны, минимум три точки, тип фигуры и структуру вырезов. Покажи пользователю число точек и границы (min/max по широте и долготе), чтобы он убедился, что зона на нужном месте.

У геозоны в интерфейсе есть вкладка **Импорт** (из файла или по ссылке) — принимает JSON платформенного формата, как экспорт (проверено созданием полигона, 2026-11-15), хотя в документации этого нет. Альтернатива: геозона типа «Полигон», GeoJSON в «Код», «Сохранить» (проверено в аккаунте). Внутренний JSON (`shape` с `[широта, долгота]`) отдавай как эталон геометрии. Подробнее — `rightech-output` и `references/import-guide.md`.
