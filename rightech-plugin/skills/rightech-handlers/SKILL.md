# Обработчики

## Блокирующее условие

Обработчик создаётся только при наличии:

1. **Модели устройства с параметрами** — файл экспорта или модель в аккаунте (`GET /api/v1/models/:id`).
2. **Реального пейлоада** — настоящего сообщения устройства (топик и тело из журнала объекта или с устройства). Придуманные значения не подходят.

Плюс сначала самостоятельно найди документацию точной модели устройства: протокол, формат пакета, единицы, коэффициенты, порядок байтов и коды статусов. Запиши URL и применимую версию в `references/device-notes.md`. Если поиск не нашёл надёжный источник — тогда спроси пользователя, есть ли руководство/таблица регистров; не проси повторно документ, который уже найден.

Чего-то из пунктов 1–2 нет — не пиши код. Документацию устройства ищи самостоятельно через `rightech-research`, но найденная спецификация не заменяет реальные входные данные. Скажи, чего не хватает, и где взять: модель — «Экспорт» у модели; payload — журнал объекта (https://rightech.io/ru/developers/objects/journal) или вывод устройства.

## Сверка до кода

Запусти `rightech-research` и прочитай найденную документацию целиком; выпиши формат, единицы, коэффициенты, порядок байтов, коды и URL источника.
- Разбери пейлоад: топик, формат (JSON, строка, бинарь), поля, типы, пропуски, `null`.
- Составь таблицу «поле пейлоада → параметр модели (`id`, `dataType`, `unit`)».
- Расхождения (поле без параметра, параметр без поля, другие типы/единицы) покажи пользователю и спроси, что делать. Реальный пейлоад важнее текста документации, но выбор подтверждает пользователь.

## Код (стиль образцов)

- Точка входа: `export function process(payload)` для JavaScript; `export function process(payload: string, topic: string)` для TypeScript.
- JSON: `JSON.parse(payload)`; не возвращай `undefined` — удаляй отсутствующие поля, чтобы не затирать состояние (`props.setUndefinedParamTo = "prev"`).
- Бинарь: `ric.base64.decode(payload)`, `DataView`, чтение little-endian (`getUint32(offset, true)`), проверка длины перед чтением, диспетчеризация по `classId`, неизвестный id → `{}`.
- Время устройств: эпоха `1980-01-01T00:00:00.000+03:00`, значение = эпоха + секунды × 1000.
- Фрагменты между пакетами: `ric.localStore.forObject.set({...})`.
- Комментарии и типы — на русском. Никаких секретов, ключей и внешних адресов в коде.

## Поля сущности

`name`, `language` (`javascript` | `typescript`), `userCode`, `props`, `description`. Связь с моделью — `parameters["m-<id модели>"]["h-<id обработчика>"].import|export`; для кросс-варианта — `elementType: "cross"`, `crossElements`, `crossMappings`. Точный вид ключей для новой сущности уточни в тестовом проекте.

## Проверка

1. Прогони код на пейлоаде пользователя и покажи вход/выход.
2. Затем валидатор:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/validate.py" handler.json --store handlers --mode new
```

3. Покажи таблицу соответствия полей и итоговый JSON без секретов.
4. Собери файлы через `rightech-output`: JSON сущности и отдельный файл кода. Импорта для обработчиков нет — пользователь создаёт обработчик, вставляет код и сохраняет.
