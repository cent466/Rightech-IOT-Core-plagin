# Открытые вопросы

Подход изменён: плагин больше не подключается к API, а отдаёт готовые файлы для ручного импорта. Перед запросом документации пользователя плагин обязан провести собственный поиск официальных источников (навык `rightech-research`). Вопросы про токен, права и тестовый проект сняты.

## Подтверждено

- Импорт из файла **есть в интерфейсе для моделей, сценариев, обработчиков, геозон и объектов**; выполняется при создании сущности (проверено на живом аккаунте 2026-11-15: вкладки «Импорт» / «Из файла» / «По ссылке»). Документация про обработчики и геозоны устарела.
- Импорт требует `_id` внутри `data` (24 hex); без него — «Ошибка: неверный формат файла». Поля `user`/`group` в оболочке не обязательны.
- У **геозон** импорт в документации не описан, но в интерфейсе есть: принимает JSON платформенного формата (полигон проверен).
- Формат файла совпадает с экспортом: `version`, `origin`, `time`, `user`, `group`, `store`, `data`.
- Сценарий хранит `data` строкой с вложенным JSON `states`/`transitions` (6/6 образцов).
- Геозона — полигон, пары `[широта, долгота]`, контур не замкнут (2/2 образца).
- Язык `name`/`description` в моделях — русский (подтверждено пользователем 2026-11-15); валидатор язык не проверяет.
- Круглая геозона подтверждена на живом аккаунте (2026-11-16): `shape: {"type": "circle", "center": [широта, долгота], "radius": <метры>}`; `multiPolygon` — `union` из `polygon`, `marker` — только `center`; прямоугольник сохраняется как `polygon` из 4 точек.
- Узла типа `event` в платформе нет: событие модели — `event-logic` (`id`, `name`, `active`, `children`), на его `id` ссылается `transitions.<id>.data.event` (2026-11-16).
- `processId` сценария необязателен: сценарий, созданный в интерфейсе, и импортированный файл без него сохраняются без этого поля (2026-11-16). Генерировать/копировать его не нужно.
- Каталог протоколов подтверждён 16 базовыми моделями платформы (2026-11-16): `arnavi3`, `autofon8`, `coap`, `egts`, `galileosky`, `http-ric`, `lora`, `lwm2m`, `mqtt`, `navtelecom`, `nidd`, `smpp`, `teltonika`, `websocket`, `wialon-combine`, `wialon-ips`. `props.protocol` совпадает с `base` не всегда (`http`→`http-ric`, `ntcb`→`navtelecom`, `wialon`→`wialon-ips`/`wialon-combine`). Подробности — `references/base-models.md`.

## Поиск документации

Выполняется самим плагином до вопросов пользователю. Ищи в официальной справке Rightech, `ref.rightech.io`, `github.com/Rightech` и у производителя точного устройства. Фиксируй URL, версию/ревизию и применимые разделы в `references/device-notes.md` или этом файле. Пользователя проси о материале только для конкретной информации, которую найти не удалось. Для обработчика документация дополняет, но не заменяет обязательные реальную модель и payload.

## Проверить при первом импорте

- Для маршрутной геозоны: JSON не получен, код платформы читает только `polygon`, `multiPolygon`, `circle` и `marker`.

## Пользовательские предпочтения

- Переносится ли `_inactive`/`copy` из шаблона в импортируемый файл: созданная модель их содержит, плагин их сохраняет, но импорт на живом аккаунте не проверялся.
- Правила именования сущностей и обязательность `description`.
- Язык обработчиков по умолчанию: JavaScript или TypeScript.
- Нужна ли публикация в каталогах Anthropic и OpenAI помимо локальной установки.
