# Импорт сущностей в Rightech

Проверено по официальной документации Rightech (2026-11-14). Импорт выполняется **вручную при создании сущности**: файл `.json` или ссылка (например, raw-файл на GitHub).

| Тип | Импорт из файла | Источник |
|---|---|---|
| Модель | ✅ «Создать модель» → импорт | https://rightech.io/ru/developers/models/share |
| Сценарий | ✅ «Создать сценарий» → импорт | https://rightech.io/ru/developers/scenarios/share |
| Объект | ✅ «Создать объект» → импорт | https://rightech.io/ru/developers/objects/share |
| Обработчик | ❌ нет: создать и вставить код | https://rightech.io/ru/developers/handlers/share |
| Геозона | ✅ GeoJSON полигона → вкладка «Код» | https://rightech.io/ru/developers/positioning/geofences |

## Формат файла

Официальные примеры импорта используют ту же оболочку, что и экспорт:

```json
{
  "version": 1,
  "origin": "dev.rightech.io",
  "time": "2021-12-24T08:27:53.583Z",
  "user": "613645025dab3700105ae872",
  "group": "613645025dab3700105ae871",
  "store": "automatons",
  "data": { "...": "..." }
}
```

Источник примера: https://github.com/Rightech/ric-examples (`docs_examples/.../Geofence control.json`).

`rightech-plugin/scripts/make_import_file.py` собирает такую оболочку без `user`/`group`/`_id`: эти значения принадлежат конкретному аккаунту. **Не подтверждено**, обязательны ли `user` и `group` при импорте; если платформа их потребует, их можно взять из экспорта любой своей сущности.

## Имена файлов

Платформа сохраняет экспорт как `<дата>_<Тип>_<имя>.json`, например `2026-11-14_Модель_Automatic_aqwa.json`. Скрипт придерживается того же шаблона.

## После импорта

- **Сценарий:** назначить модель и сопоставить кросс-элементы — платформа после импорта этого не делает.
- **Модель:** при необходимости привязать обработчики и создать объекты.
- **Обработчик:** вставить код в редактор, затем задать входные/выходные параметры; `parameters` и `crossMappings` из JSON ссылаются на идентификаторы уже существующих сущностей и вручную переносятся через интерфейс.
- **Геозона:** создать полигон на карте, затем вставить GeoJSON в вкладку «Код» и сохранить — проверено пользователем в аккаунте (2026-11-14); контур должен быть замкнут, пары `[долгота, широта]`. Внутренний формат экспорта использует `[широта, долгота]`. Формат круга по-прежнему неизвестен. Точный контур реального объекта (МКАД, район, граница региона) бери из Overpass Turbo — инструкция и скрипт `scripts/geojson_zone.py` описаны в навыке `rightech-geofences`.

## Ограничения

- Импорт не проверялся на живом аккаунте: вывод сделан по документации и официальным примерам.
- Лимиты на размер файла и число узлов не подтверждены.
