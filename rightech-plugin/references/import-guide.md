# Импорт сущностей в Rightech

Проверено на живом аккаунте `dev.rightech.io` (2026-11-15): импорт выполняется **вручную при создании сущности**, файлом `.json` или по ссылке (например, raw-файл на GitHub). Проверка шла через вкладку «По ссылке», чтобы исключить влияние выбора файла в диалоге ОС.

| Тип | Импорт при создании | Как выглядит |
|---|---|---|
| Модель | ✅ | «Создать» → «Загрузить готовую модель» → вкладки «Из файла» / «По ссылке» |
| Сценарий | ✅ | «Создать» → «Создание нового сценария» → вкладки «Новый сценарий» / «Импорт» (внутри «Из файла» / «По ссылке») |
| Обработчик | ✅ | «Создать» → «Создание нового обработчика» → вкладки «Новый обработчик» / «Импорт» |
| Объект | ✅ | «Создать объект» → импорт |
| Геозона | ⚠️ | не файлом: GeoJSON полигона вставляется во вкладку «Код» |

Официальная документация Rightech утверждает, что импорта обработчиков нет (https://rightech.io/ru/developers/handlers/share) — в интерфейсе он есть, проверено созданием обработчика из файла.

## Обязательное поле `_id`

Импорт принимает только объект, у которого внутри `data` есть `_id` — идентификатор в формате ObjectId платформы (24 шестнадцатеричных символа). Без него платформа отвечает **«Ошибка: неверный формат файла»**, даже если всё остальное корректно.

Проверено перебором вариантов одного и того же файла модели:

| Файл | Результат |
|---|---|
| оболочка + `data` без `_id` (с `user`/`group` и без них) | ❌ «неверный формат файла» |
| оболочка + `data._id` | ✅ «Файл успешно загружен!» |
| оболочка + `data` c `_id`, `owner`, `group`, `time` | ✅ «Файл успешно загружен!» |

`user` и `group` в оболочке не обязательны: файл без них импортируется. Платформа берёт _id из файла — созданная сущность получила именно тот идентификатор, что был в `data._id`.

## Формат файла

Официальные примеры импорта используют ту же оболочку, что и экспорт:

```json
{
  "version": 1,
  "origin": "dev.rightech.io",
  "time": "2021-12-24T08:27:53.583Z",
  "user": "613645025dab3700105ae872",
  "group": "613645025dab3700105ae871",
  "store": "automatons",
  "data": { "_id": "6af9735c82eb553c90e4f071", "...": "..." }
}
```

`store` — тип сущности: `models`, `automatons`, `handlers`, `geofences`. `data` — сама сущность; для сценария поле `data` внутри неё остаётся строкой с JSON состояний и переходов.

Источник примера оболочки: https://github.com/Rightech/ric-examples (`docs_examples/.../Geofence control.json`).

`rightech-plugin/scripts/make_import_file.py` собирает оболочку сам и всегда добавляет `data._id`:

- `--id <24 hex>` — задать идентификатор явно (по умолчанию генерируется: время + случайная часть);
- `--user` / `--group` — подставить идентификаторы аккаунта из любого своего экспорта (не обязательны);
- `--origin` — хост платформы для поля `origin` (по умолчанию `dev.rightech.io`).

## Имена файлов

Платформа сохраняет экспорт как `<дата>_<Тип>_<имя>.json`, например `2026-11-14_Модель_Automatic_aqwa.json`. Скрипт придерживается того же шаблона. Имя файла на импорт не влияет — важен только JSON внутри.

## После импорта

- **Сценарий:** проверить, что модель найдена и кросс-элементы сопоставлены; тип сценария («по кросс-элементам» / «по параметрам из модели») фиксируется при создании и меняться не может.
- **Модель:** при необходимости привязать обработчики и создать объекты.
- **Обработчик:** задать входные/выходные параметры; `parameters` и `crossMappings` из JSON ссылаются на идентификаторы уже существующих сущностей и вручную переносятся через интерфейс.
- **Геозона:** создать полигон на карте, затем вставить GeoJSON `Feature/Polygon` во вкладку «Код» и сохранить — проверено пользователем в аккаунте (2026-11-14); координаты `[долгота, широта]`, контур замкнут. `FeatureCollection` сначала разбирается по целевому feature. `MultiLineString` нельзя замыкать автоматически: выяснить, нужна ли область внутри кольца или полоса/буфер. Скрипт `scripts/geojson_zone.py` сохраняет выбранные Polygon без изменений и отказывается от неоднозначных/линейных входов. Внутренний формат экспорта использует `[широта, долгота]`. Формат круга по-прежнему неизвестен.

## Ограничения

- Импорт по ссылке платформа выполняет сама: нужен публично доступный URL, локальный путь не подойдёт.
- Лимиты на размер файла и число узлов не подтверждены.
- Как ведёт себя импорт при совпадении `_id` с уже существующей сущностью, не проверено.
