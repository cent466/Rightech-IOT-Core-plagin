# SVG параметров и локальный replay

Эти инструменты работают с файлами, без API и команд устройствам. Они проверяют
ограниченное подмножество модели. Локально успешный результат не подтверждает
импорт в RIC, серверное поведение или работу физического устройства.

Из корня репозитория скрипты находятся в `rightech-plugin/scripts/`. В изолированной
копии навыка `rightech-output` используй её собственные `scripts/`, `schemas/`
и `examples/model-tools/`: сборщик плагина поставляет их вместе.

XML-проверка SVG и основная проверка сущностей не требуют сторонних пакетов.
Для рисования по JSON-геометрии, PNG и replay установи дополнительные зависимости:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r rightech-plugin/requirements-tools.txt
```

В изолированной копии навыка этот же файл называется `requirements-tools.txt`.
CairoSVG также требует системную библиотеку Cairo. Если зависимость недоступна,
инструмент сообщает `not_tested` и возвращает ненулевой код.

## SVG

Когда нужны иконки параметров, самостоятельно нарисуй векторную геометрию по
смыслу величины. Не ограничивайся подбором одной готовой картинки. Можно написать
SVG напрямую либо описать произвольные примитивы по `schemas/drawing.schema.json`.
Примеры геометрии иллюстрируют стиль, но не ограничивают набор допустимых образов.

Предпочтительный исходный масштаб — `viewBox="0 0 16 16"`, с отступом от края
около 1 px, без мелких надписей. Не рисуй текущее значение внутри иконки.
Сохраняй `fill="none"`; для изменяемого цвета используй наследование заливки.
Фиксированный белый фон мешает тёмной теме. Обводку и `currentColor` отдельно
проверь на целевой RIC: локальный рендер моделирует перекраску, но не реализацию UI.

```bash
.venv/bin/python rightech-plugin/scripts/draw_svg.py \
  rightech-plugin/examples/model-tools/drawings/temperature.json -o rightech-output/icons/temperature.svg
python3 rightech-plugin/scripts/validate_svg.py rightech-output/icons --strict
.venv/bin/python rightech-plugin/scripts/render_svg.py rightech-output/icons \
  -o rightech-output/svg-preview.png
```

Посмотри PNG в реальных размерах 16, 24 и 32 px, на двух фонах и в трёх цветах
состояния. Эти размеры — контрольные образцы, а не универсальная геометрия RIC.
Другие размеры задаются `--sizes`. Ноль видимых пикселей или пиксели на границе
образца завершают проверку с кодом 1; узнаваемость оценивается визуально.
При отсутствии растеризатора остаётся HTML, но PNG-проверка получает `not_tested`.

Встрой точную строку SVG в `display.svg` и/или `levels.svg`. Если заданы обе копии,
они должны совпадать. `display.indicator: true` включает индикатор согласно
контракту целевой платформы. Иконка не меняет единицу, `linear` или источник.
Обычные модели без собственных SVG остаются допустимыми.

Скрипты, обработчики событий XML, DTD/entities, внешние ресурсы и активные элементы
запрещены. В режиме `export` отклонения старых иконок от ограниченного переносимого
профиля отмечаются предупреждениями; активное содержимое остаётся ошибкой.
Не переписывай сложные исторические иконки автоматически. Рендер новых иконок
использует строгий профиль без внешних изображений, шрифтов и CSS.

## Replay

```bash
.venv/bin/python rightech-plugin/scripts/replay_cases.py \
  rightech-plugin/examples/model-tools/model.json \
  rightech-plugin/examples/model-tools/cases.json --out rightech-output/replay.json
```

Вход модели — голая модель или оболочка `version: 1`, `store: models`.
Набор проверок имеет `schema_version: "1.0"` и непустой `cases` по
`schemas/cases.schema.json`. Каждый случай содержит `name`, `kind`, `synthetic`
и независимые ожидания: `expected`/`absent` для параметров либо `expected_command`
для команды. Отмечай синтетические пакеты; они не становятся настоящими данными.

Поддержанное подмножество:

- `kind: mqtt`: скалярный топик или JSON-объект, ссылки через ID JSON-контейнера;
- `kind: decoded`: уже декодированные адресованные поля, индексы `.0`, `.1`;
- биты целого источника только при явном `bit_sources`; без этого случай не проверен;
- числовой `factor`, отдельное различение `0`, `false`, `null`, отсутствия и строковых кодов;
- `kind: command`: подстановка переменных, типы и min/max входов, проверка JSON
  при `payload_format: json`. Можно передать полный ID входа или его короткий
  суффикс; противоречивые или неоднозначные псевдонимы отклоняются.

Каждый пакет проверяется независимо, с пустым локальным состоянием. Нет эмуляции
накопленного состояния, слияния и очистки массивов, `parser`, сложного наследования,
корневого MQTT batch, сетевых декодеров и выполнения обработчиков. Для них нужен
отдельный платформенный тест. Неподдержанное поведение получает `not_tested`,
в том числе когда ожидалось отсутствие неподдержанного параметра.

Отчёт содержит `passed_count`, `failed_count`, `not_tested_count` и
`ric_verified: false`. Он не содержит сырой payload и фактические значения
несовпадений. Код 0 означает успешные локальные ожидания, 1 — несовпадение или
неподдержанный случай, 2 — неверный вход/недоступный инструмент.

## Выдача

Выдай модель, исходные SVG, тестовые случаи и сводку проверки. Разделяй статическую
проверку, replay, SVG-рендер, импорт на RIC и испытание устройства. До соответствующей
проверки RIC и устройство имеют статус `not_tested`; наличия локального файла
импорта для изменения этого статуса недостаточно.
