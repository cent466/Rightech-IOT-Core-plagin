# Rightech IoT Core — плагин генерации файлов сущностей

Плагин помогает Claude Code и Codex создавать JSON-файлы сущностей Rightech IoT Core по локальным образцам и доступной документации. Результат — готовый файл для ручного импорта или переноса через интерфейс Rightech.

**Плагин не подключается к API Rightech, не просит пароль или токен и сам ничего не загружает в аккаунт.**

## Скачать и установить

Нужны Git и соответствующий клиент Claude Code или Codex.

### Claude Code — установить из GitHub Marketplace

В терминале Claude Code выполните:

```bash
claude plugin marketplace add cent466/Rightech-IOT-Core-plagin
claude plugin install rightech@rightech-plugins
```

Проверить установку:

```bash
claude plugin marketplace list
claude plugin list
```

Если клиент сообщает, что плагин установлен, но ещё не загружен, перезапустите Claude Code или начните новую сессию.

### Codex — установить из GitHub Marketplace

В терминале Codex выполните:

```bash
codex plugin marketplace add cent466/Rightech-IOT-Core-plagin
codex plugin add rightech@rightech-plugins
```

После установки перезапустите Codex. Возможности плагинов зависят от используемого приложения/клиента Codex.

### Локальная установка из клона

```bash
git clone https://github.com/cent466/Rightech-IOT-Core-plagin.git
cd Rightech-IOT-Core-plagin
```

Claude Code из корня репозитория:

```bash
claude plugin marketplace add .
claude plugin install rightech@rightech-plugins
```

Одноразовый запуск Claude Code без регистрации маркетплейса:

```bash
claude --plugin-dir ./rightech-plugin
```

Codex из корня репозитория:

```bash
codex plugin marketplace add .
codex plugin add rightech@rightech-plugins
```

## Что делает плагин

1. Читает описание задачи и локальные образцы `primer_*`.
2. Самостоятельно ищет документацию Rightech и точного устройства в официальных источниках до того, как запросить материалы у пользователя.
3. Задаёт только вопросы, на которые не удалось найти подтверждённого ответа, и получает подтверждение спецификации до генерации.
4. Собирает JSON по ближайшему образцу, проверяет структуру локальным валидатором и сохраняет результат в файлы.
5. Даёт инструкцию по ручному импорту или переносу в интерфейсе.

Документы исследования должны указывать источники, модель и версию. Если поиск недоступен в среде, плагин должен прямо сообщить об этом; он не должен утверждать, что выполнил поиск.

## Какие файлы создаются

| Сущность | Результат | Как переносится в Rightech |
|---|---|---|
| Модель | `YYYY-MM-DD_Модель_<имя>.json` | Импорт файла при создании модели |
| Сценарий | `YYYY-MM-DD_Сценарий_<имя>.json` | Импорт файла при создании сценария; после импорта назначить модели/сопоставления, если нужно |
| Обработчик | JSON сущности и отдельный `.js`/`.ts` с `userCode` | Создать обработчик вручную, вставить код и сохранить; файловый импорт не документирован |
| Геозона | JSON с формой и координатами | Файловый импорт не документирован; JSON служит спецификацией для создания на карте |

Файлы сохраняются в каталоге `rightech-output/` текущего проекта/рабочей папки. Небольшой JSON плагин может показать целиком в ответе; большие модели и полигоны он описывает сводкой и путём к файлу.

## Правила для обработчиков

Обработчик не генерируется по одним догадкам. Требуются:

- модель устройства с настоящими параметрами;
- реальное сообщение/payload от устройства.

Плагин сначала сам ищет документацию устройства. Если не находит надёжный источник, он просит руководство или таблицу регистров; найденная документация не заменяет реальные модель и payload. При расхождениях документации, payload и модели плагин должен показать их и уточнить выбор.

## Ручная сборка файлов

Из корня репозитория:

```bash
# Проверить JSON-экспорт или подготовленную сущность
python3 rightech-plugin/scripts/validate.py path/to/entity.json

# Создать готовый файл модели
python3 rightech-plugin/scripts/make_import_file.py model.json --store models

# Другие типы: automatons, geofences, handlers
python3 rightech-plugin/scripts/make_import_file.py entity.json --store automatons

# Указать собственный хост в поле origin для on-premise
python3 rightech-plugin/scripts/make_import_file.py model.json --store models --origin ric.example.org
```

Параметр `--store` можно не указывать, если тип однозначно определяется по полям файла. Для обработчика скрипт сохранит JSON и исходный файл кода с расширением `.js` или `.ts`.

├── primer_obrabotka/                 исходные экспорты обработчиков
├── references/                       аудит, правила и индекс исходных образцов

    ├── .codex-plugin/plugin.json

## Проверки проекта

Из корня репозитория:

```bash
python3 rightech-plugin/scripts/validate.py rightech-plugin/references/samples
python3 -m unittest discover -s rightech-plugin/tests
claude plugin validate ./rightech-plugin
claude plugin validate .
```

Ожидается: 24 образца проходят валидатор без ошибок; Python-тесты завершаются успешно.

## Ограничения и открытые вопросы

- Импорт моделей и сценариев по JSON описан в документации Rightech. Импорт обработчиков отсутствует; импорт геозон в изученной документации не описан. Инструкции и ссылки: `rightech-plugin/references/import-guide.md`.
- Формат круглой геозоны, узла модели `event`, полный набор действий сценариев и некоторые платформенные поля не подтверждены имеющимися образцами. Плагин должен сначала искать документацию, а при неудаче запросить экспорт или точный технический материал.
- Формат упаковки файла повторяет платформенные экспорты и опубликованные примеры; импорт каждого собранного файла не был проверен на реальном аккаунте. В частности, пока не подтверждено, обязательны ли `user` и `group`.
- Перед импортом сценария может потребоваться `_id` уже существующей модели.

## Безопасность и приватность

- Для работы генератора не нужны `RIGHTECH_TOKEN`, пароль или API-ключ.
- Не помещайте секреты, payload с персональными/конфиденциальными данными и экспорты с приватными данными в публичный репозиторий без проверки доступа и очистки.
- Сырые образцы в `primer_*` входят в комплект; перед публикацией убедитесь, что их публикация разрешена и они не содержат данных устройств или владельцев, которые не следует раскрывать.
- `.freebuff/`, `.env`, токены, локальные кэши и сгенерированные результаты не входят в репозиторий.
