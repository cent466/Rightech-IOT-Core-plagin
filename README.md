# Rightech IoT Core — плагин для Claude и Codex

Плагин помогает собрать готовые JSON-файлы сущностей Rightech IoT Core: **моделей устройств**, **сценариев автоматизации**, **геозон** и **обработчиков**. Вы описываете задачу обычными словами — плагин задаёт уточняющие вопросы, сверяется с документацией и рабочими экспортами, проверяет результат и отдаёт файл, который остаётся импортировать в интерфейсе Rightech.

Плагин работает **локально и офлайн**: не подключается к API, не просит токен, пароль или доступ к аккаунту и ничего не загружает в Rightech сам.

📘 **[Подробная инструкция: как пользоваться и что умеет плагин →](./USAGE.md)** — пошаговые разборы по каждому типу сущности, подготовка данных, проверка и решение типичных проблем.

---

## Что можно получить

| Что нужно | Что вернёт плагин | Как попадёт в Rightech |
|---|---|---|
| Модель устройства | `2026-11-15_Модель_<имя>.json` — дерево подсистем, параметров и команд | Модели → Создать → Импорт файла |
| Сценарий автоматизации | `2026-11-15_Сценарий_<имя>.json` — состояния, переходы, действия | Сценарии → Создать → Импорт файла, затем назначить модели |
| Обработчик (userCode) | JSON сущности + отдельный `<имя>.js` или `.ts` с кодом | Обработчики → Создать → «Импорт» → файл (или вставить код) |
| Геозона | JSON с координатами и GeoJSON для вкладки «Код» | Геозоны → Создать → «Импорт» → файл (или вставить GeoJSON) |

Готовые файлы складываются в папку `rightech-output/` текущего проекта. Небольшой JSON плагин покажет прямо в ответе, большой (модель на сотни параметров, полигон на тысячи точек) — опишет сводкой и путём к файлу.

## Установка

### Claude Desktop / Claude.ai — загрузка ZIP

1. Скачайте [готовый архив `rightech-plugin-claude.zip`](https://github.com/cent466/Rightech-IOT-Core-plugin/raw/refs/heads/main/rightech-plugin-claude.zip).
2. В Claude откройте **Персонализация → Плагины → Добавить → Загрузить плагин**.
3. Выберите скачанный ZIP (внутри лежит папка `rightech-plugin/` с манифестом).
4. Включите **Code execution and file creation** в **Настройки → Возможности** — без этого недоступны проверка и сохранение файлов.
5. Проверьте, что навыки плагина включены в **Персонализация → Навыки**, и начните новый чат.

Для ZIP-установки Git и терминал не нужны. Нужен тариф с поддержкой навыков (Pro, Max, Team или Enterprise).

### Claude Code

```bash
claude plugin marketplace add cent466/Rightech-IOT-Core-plugin
claude plugin install rightech@rightech-plugins
```

Проверить: `claude plugin list`. Если плагин установлен, но ещё не загружен, начните новую сессию.

### Codex

```bash
codex plugin marketplace add cent466/Rightech-IOT-Core-plugin --ref main
codex plugin add rightech@rightech-plugins
```

Либо запустите `codex /plugins`, выберите маркетплейс **Rightech Plugins** и установите `rightech`. В приложении ChatGPT/Codex тот же маркетплейс открывается на вкладке **Plugins**. Расширение IDE плагины не поддерживает.

Обновление: `codex plugin marketplace upgrade rightech-plugins`.

### Локально из клона

```bash
git clone https://github.com/cent466/Rightech-IOT-Core-plugin.git
cd Rightech-IOT-Core-plugin
claude plugin marketplace add .
claude plugin install rightech@rightech-plugins
```

Разовый запуск Claude Code без установки: `claude --plugin-dir ./rightech-plugin`.
Для Codex: `codex plugin marketplace add .` и `codex plugin add rightech@rightech-plugins`.

## Как пользоваться

1. **Опишите задачу** в новом чате: что за устройство или процесс, что должно происходить, какой результат нужен.
2. **Ответьте на вопросы.** Плагин сначала попробует найти ответ в официальной документации Rightech и производителя, а спросит только то, что не удалось подтвердить. Если в задаче не хватает логики, он не станет её выдумывать.
3. **Подтвердите спецификацию** — короткий пересказ того, что будет собрано.
4. **Заберите файл** из `rightech-output/` и импортируйте его по инструкции, которую плагин добавит в ответ.

### Примеры запросов

**Модель.** «Сделай модель для датчика уровня воды. Вот руководство и пример сообщения: … Название — „Уровень воды в резервуаре“».

Плагин попросит документацию устройства (паспорт, протокол, таблицу параметров с ключами и единицами) и только по ней построит `reference`, типы и команды. Придумывать параметры и единицы он не будет.

**Сценарий.** «Нужен сценарий: если температура выше 30 °C держится 10 минут — включить вентилятор и отправить уведомление. Шаги: Ожидание → Перегрев → Охлаждение. Переход в „Перегрев“ по событию телеметрии с условием по температуре, обратно — когда температура ниже 28 °C».

Состояния, события и условия переходов должны прийти от вас: по одному названию задачи плагин логику не достроит. Названия состояний он предложит на русском.

**Обработчик.** «Напиши обработчик для этого payload и этой модели: нужно разобрать пакет и заполнить параметры».

Для обработчика обязательны два входных материала: экспорт модели с деревом параметров и **реальное** сообщение из журнала объекта (топик и тело как есть). Без них плагин код не пишет — документация и синтетический пример их не заменяют.

**Геозона.** «Сделай геозону по этому контуру» — приложите GeoJSON или координаты.

Если контур нужен по реальному месту (район, промзона, озеро), плагин отправит вас за точной геометрией в Overpass Turbo, а не будет рисовать её на глаз.

## Что плагин спросит обязательно

| Сущность | Обязательные входные данные |
|---|---|
| Модель | документация устройства, название и краткое описание модели |
| Сценарий | название и краткое описание, шаги/состояния и условия переходов |
| Обработчик | экспорт модели, реальный payload, название и краткое описание |
| Геозона | координаты или готовый контур |

Это не формальности: без подтверждённых данных плагин останавливается и просит недостающее, а не подставляет похожие значения из образцов.

## Импорт в Rightech

- **Модель** — «Создать» → «Загрузить готовую модель» → файл.
- **Сценарий** — «Создать» → вкладка «Импорт» → файл; после импорта назначьте модель и сопоставьте кросс-элементы, если сценарий их использует.
- **Обработчик** — «Создать» → вкладка «Импорт» → файл; альтернатива — вставить код из `.js`/`.ts` вручную. Связи с моделью задаются в интерфейсе.

- **Геозона** — «Создать» → вкладка «Импорт» → файл платформенного формата; альтернатива — вставить GeoJSON `Feature/Polygon` во вкладку «Код» и сохранить.

В каждом случае вместо файла можно указать ссылку на него. Обязательное условие — `_id` внутри `data`: без него платформа отвечает «Ошибка: неверный формат файла», и плагин генерирует его автоматически.

Готовые файлы проверки лежат в каталоге [`import-ready/`](./import-ready). У каждого файла на GitHub есть кнопка Raw — эту ссылку можно вставить во вкладку «По ссылке» при создании сущности.

Подробнее, со ссылками на документацию Rightech: [`rightech-plugin/references/import-guide.md`](./rightech-plugin/references/import-guide.md).

## Что внутри

Плагин состоит из восьми навыков, которые включаются по типу задачи:

| Навык | Зачем |
|---|---|
| `rightech-models` | модели устройств: подсистемы, параметры, команды |
| `rightech-scenarios` | сценарии: состояния, переходы, действия, уведомления |
| `rightech-handlers` | обработчики `userCode` по модели и реальному payload |
| `rightech-geofences` | геозоны, полигоны, GeoJSON |
| `rightech-questions` | обязательные уточняющие вопросы до генерации |
| `rightech-research` | самостоятельный поиск документации, если её не дали |
| `rightech-output` | сборка файла, проверка и инструкция по импорту |

В комплект входят офлайн-валидатор, который проверяет структуру, ссылки, координаты сценариев и секреты в коде, и правила, выведенные из рабочих экспортов. Сами экспорты и тесты на них в публичный репозиторий не входят — они лежат в закрытой части.

Каталог из 16 протоколов платформы — MQTT, HTTP, LoRaWAN, NIDD, CoAP, LwM2M, WebSocket, SMPP, Wialon IPS и Combine, EGTS, Teltonika, Galileosky, Arnavi3, Автофон, Navtelecom — с точными парами `base`/`props.protocol`, `idPattern`, протокольными настройками и формами команд: [`rightech-plugin/references/base-models.md`](./rightech-plugin/references/base-models.md). Модель под неподтверждённый протокол плагин не собирает.

## Ручные команды

Если нужно проверить или собрать файл без чата, из корня репозитория:

```bash
# проверить экспорт или подготовленный JSON
python3 rightech-plugin/scripts/validate.py path/to/entity.json

# собрать файл для импорта (появится в rightech-output/)
python3 rightech-plugin/scripts/make_import_file.py entity.json --store models

# подготовить Polygon из GeoJSON для вкладки «Код»
python3 rightech-plugin/scripts/geojson_zone.py zone.json -o rightech-zone.json
```

`--store` принимает `models`, `automatons`, `geofences`, `handlers`; для своего сервера добавьте `--origin your.rightech.host`.

### Проверки проекта

```bash
claude plugin validate ./rightech-plugin   # манифест Claude
python3 scripts/check_manifests.py         # манифесты плагина и маркетплейсов
python3 scripts/check_zip.py               # ZIP совпадает с rightech-plugin/
python3 rightech-plugin/scripts/validate.py import-ready
```

Если правили навыки, скрипты или README плагина, пересоберите архив: `python3 scripts/check_zip.py --write`. Те же проверки выполняет GitHub Actions (`.github/workflows/plugin-checks.yml`) на каждый push в `main` и pull request.

Проверки на 25 эталонных образцах и 64 теста выполняются в закрытой части плагина: образцы не публикуются.

## Ограничения

- Импорт моделей, сценариев, обработчиков и геозон есть в интерфейсе и проверен на живом аккаунте (2026-11-15): все четыре сущности создались из файлов, в том числе через вкладку «Из файла».
- Поля `user` и `group` в оболочке не обязательны. Не подтверждены: круглая геозона, узел модели `event`, полный каталог системных событий и действий сценариев.
- Плагин проверяет структуру JSON, но не запускает сценарии на объектах и не исполняет `userCode` обработчика. Поведение обработчика проверяется отдельно — на реальном payload.
- Для сценария может понадобиться `_id` уже созданной модели; придумывать его плагин не будет.

---

## Безопасность и приватность

- Плагин не запрашивает и не хранит токены, пароли и ключи.
- В готовые файлы не попадают служебные поля аккаунта: `_id`, `owner`, `group`, `time` и подобные.
- Всё, что уходит в Rightech, пользователь загружает сам через интерфейс.
- Экспорты из вашего аккаунта и эталонные образцы в этот репозиторий не попадают: они хранятся в закрытой части, а публикуются только сам плагин, документация и готовые файлы в `import-ready/`.
